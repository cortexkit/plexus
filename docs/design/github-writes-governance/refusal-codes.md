# GitHub bot write refusal codes

Every code the `github` tool's `bot_request` operation can return, read from
the source at commit 3a5c2312. Callers such as AFT's gh shim, which routes
agents' `gh` commands through plexus, use it to tell an agent whether anything
reached GitHub, whether retrying the same request nonce is safe, and who has
to act.

Where codes appear: the facade's own refusals are in `result.refusal_code`
(some also carry `result.code` and a `detail` object). Refusals from the
module's earlier gates are a top-level `error.code`. When a reply carries
`transmission: "not_sent"`, no write was sent for that request. The
`review_thread_not_own` refusal sets `result.transmission` after its pre-dispatch
reads. A non-empty `legs_sent` lists write steps that did reach GitHub before
the refusal.

## Glossary

- Request nonce: the caller-supplied `request_nonce` string that names one bot request attempt; the receipt is keyed by agent plus nonce.
- Receipt: the stored `github_bot_receipt` row for one agent plus nonce, holding the request fingerprint, write steps, claim, outcome and refusal.
- Claim and "no claim": the lease (`claim_owner` plus expiry) giving one worker exclusive dispatch of the receipt's unsent write steps; "no claim" means no worker holds or finished that receipt, so the same nonce can simply be sent again.
- Write step: one planned GitHub write the facade dispatches in order; `legs_sent` names the write steps already sent.
- Gates G1 to G10: G1 checks the route scope delegates to an agent; G2 checks the agent handle and repository binding; G3 checks the request shape; G4 checks the existing receipt; G5 checks the handle is enabled and proven; G6 checks grants and policy; G7 takes the claim; G8 runs pre-dispatch reads and ownership checks; G9 rechecks the receipt baseline; G10 dispatches each write.
- Call modes: Classic is a direct module call; Flow is a Basal-carried call with a flow stamp; Codemode is a model run that never acts as an agent and cannot use `bot_request`.
- Connector home and "held": the single-machine lease for outside effects; "held" means this machine currently holds it and may dispatch.
- Route scope, delegating scope and run scope: the route scope is the daemon-stamped session the route was bound under; a delegating scope delegates, names an agent and is owner-authorized so it may act as that agent; a run scope is an extra liveness check that must stay a live child of the route scope, so a revoked session stops further writes.
- Flow carrier and "admitted": the module principal carrying a flow call; "admitted" means it is Basal, the only principal allowed to carry flows.
- Flow audience: the approved repository set a flow may use (Global, Workspace or Agent), checked before dispatch.
- Route epoch: the daemon's generation counter for a route channel; the binding is keyed on channel plus epoch.
- Binding ticket: the operator-issued single-use ticket consumed to bind a connection; credential material only enters this way.
- Receipt baseline: the authority snapshot pinned on the receipt at claim and rechecked before each write; drift refuses as `stale_authority`.

## `retry_same_nonce`

Every `bot_request` refusal now carries `retry_same_nonce` beside its code: in `result` for facade refusals, in `error` for module refusals. It is additive and never changes the code or other bytes. `true` means resending the identical request with the same nonce is safe: either the refusal never claimed the receipt (all admission refusals except `nonce_payload_mismatch`, including `invalid_request`, `request_field_forbidden` and `stale_authority` from `expect`), or the facade released the claim so the retry skips already-sent write steps and resumes at the first unsent one. `true` for `nonce_in_flight` means wait, then retry the same nonce, since another owner still holds the receipt. `false` means resending the identical request with the same nonce cannot succeed, so make a new attempt with a new nonce: the receipt was finished as refused and the same nonce replays the refusal (including stored replays of a terminal refusal), or the nonce already belongs to a different payload (`nonce_payload_mismatch`).

"GitHub transmission" covers any GitHub request, reads included. "Maybe"
means the answer depends on how far the request got: a refusal at a later
step can follow earlier reads or writes. "No claim" means the refusal did not
take or finish the nonce's receipt, so the same nonce can simply be sent
again. "Who must act" is guidance from what each check enforces.
